# HTML5 문서 구조화와 웹 폼의 이해

이번 장에서는 단순히 화면에 내용을 출력하는 수준을 넘어, HTML5 문서를 의미 있게 구조화하는 방법과 사용자로부터 정보를 입력받는 웹 폼의 구성 방식을 다루었다. 이전 장에서 여러 태그를 이용해 웹 페이지의 내용을 만드는 방법을 익혔다면, 이번 장에서는 그 내용들을 어떤 기준으로 나누고 배치해야 하는지에 초점이 맞춰져 있었다. 특히 HTML5의 시맨틱 태그와 웹 폼은 실제 웹 페이지가 어떤 구조로 만들어지고 사용자와 어떻게 상호작용하는지를 이해하는 데 중요한 부분이었다.

가장 먼저 이해한 것은 시맨틱 태그의 필요성이다. 기존에는 `<div>`나 `<table>` 등을 이용해 영역을 나누는 경우가 많았지만, 이러한 방식만으로는 소스 코드를 보았을 때 각 영역이 어떤 역할을 하는지 바로 파악하기 어렵다. HTML5에서는 `<header>`, `<nav>`, `<section>`, `<article>`, `<aside>`, `<footer>`와 같이 의미가 명확한 태그를 사용해 페이지를 구성할 수 있다. 예를 들어 `<header>`에는 페이지의 제목이나 소개를, `<nav>`에는 메뉴나 링크를, `<section>`에는 본문을, `<article>`에는 각각의 독립적인 내용을 배치한다. 이렇게 작성하면 단순히 화면을 나누는 것을 넘어 문서 자체의 구조와 의미를 코드에 표현할 수 있다.

이 과정에서 특히 중요하다고 느낀 것은 문서의 구조와 화면의 모양이 서로 다른 개념이라는 점이다. 시맨틱 태그를 사용한다고 해서 각 영역의 위치나 색상이 자동으로 정해지는 것은 아니다. HTML은 각 영역이 무엇을 의미하는지를 표현하고, 실제 크기나 위치, 배경색과 같은 시각적인 부분은 CSS가 담당한다. 실습에서는 `width`, `height`, `float`, `clear` 등을 사용해 `<header>`, `<nav>`, `<section>`, `<aside>`, `<footer>`의 위치를 직접 조정해 보았다. 이 과정에서 HTML이 뼈대를 만들고 CSS가 그 뼈대를 실제 화면에 배치하고 꾸미는 역할을 한다는 관계를 좀 더 명확하게 이해할 수 있었다.

기본적인 구조화 태그 외에도 `<figure>`, `<figcaption>`, `<details>`, `<summary>`, `<mark>`, `<time>`, `<meter>`, `<progress>`와 같은 태그를 배웠다. `<figure>`와 `<figcaption>`을 사용하면 이미지나 코드, 실행 결과와 그에 대한 설명을 하나의 의미 있는 단위로 묶을 수 있다. `<details>`와 `<summary>`는 사용자가 제목을 클릭했을 때 필요한 내용을 펼치거나 다시 접을 수 있도록 구성할 수 있어서 단순한 문서에도 어느 정도의 상호작용을 추가할 수 있다는 점이 흥미로웠다. 또한 `<meter>`와 `<progress>`처럼 값이나 진행 정도를 표현하기 위한 태그가 따로 있다는 점도 알게 되었다.

후반부에서는 웹 폼을 이용해 사용자에게 정보를 입력받는 방법을 학습했다. 웹 폼은 로그인, 검색, 회원가입, 예약 등 실제 웹 서비스에서 사용자가 직접 정보를 입력하는 거의 모든 과정의 기본이 된다. `<form>` 내부에 `<input>`, `<textarea>`, `<select>` 등의 요소를 배치하고, 입력 목적에 따라 `text`, `password`, `checkbox`, `radio`, `number`, `range`, `color` 등 다양한 형식을 사용할 수 있었다. 같은 `<input>` 태그라도 `type` 속성에 어떤 값을 지정하는지에 따라 텍스트 입력창, 체크박스, 라디오 버튼, 색상 선택기, 슬라이더 등 완전히 다른 입력 요소가 된다는 점이 인상적이었다.

폼을 단순히 화면에 보여주는 것에서 끝내지 않고 입력한 데이터가 어떻게 전달되는지도 살펴보았다. `<form>`의 `action` 속성은 입력 데이터를 처리할 서버 프로그램을 지정하고, `method`는 데이터를 전달하는 방식을 지정한다. 대표적인 방식으로 GET과 POST가 있으며, 사용자가 값을 입력한 뒤 submit 버튼을 누르면 브라우저가 입력된 정보를 서버로 전달하고 서버에서 처리한 결과를 다시 사용자에게 보여주는 구조라는 것을 알게 되었다. 이전에는 검색창이나 로그인창을 당연하게 사용했지만, 이번 내용을 통해 그 뒤에서 어떤 흐름으로 데이터가 이동하는지 조금이나마 이해할 수 있었다.

또한 `<label>`, `<fieldset>`, `<legend>`를 이용하여 여러 입력 요소를 좀 더 체계적으로 구성하는 방법도 실습했다. `<label>`은 입력창과 그에 대한 설명을 연결하고, `<fieldset>`은 관련된 입력 요소들을 하나의 영역으로 묶으며, `<legend>`는 해당 영역의 제목을 나타낸다. 입력 항목이 몇 개 없을 때는 큰 차이가 없어 보이지만, 폼의 규모가 커질수록 이런 방식으로 요소들의 관계를 명확하게 만드는 것이 코드의 가독성과 관리 측면에서 중요할 것이라고 생각했다.

이번 장을 학습하면서 HTML을 바라보는 관점도 조금 달라졌다. 처음에는 HTML을 브라우저 화면에 글자나 이미지, 입력창을 출력하기 위한 언어라고 생각했지만, 시맨틱 태그와 웹 폼을 직접 사용해 보면서 HTML의 중요한 역할 중 하나는 각각의 콘텐츠에 의미를 부여하고 문서 전체의 구조를 명확하게 만드는 것이라는 점을 알게 되었다.

결국 잘 작성된 HTML은 단순히 브라우저에서 원하는 결과가 출력되는 코드에 그치는 것이 아니라, 소스 코드만 보더라도 각 영역이 어떤 역할을 하는지 어느 정도 이해할 수 있어야 한다고 생각한다. 이번 장은 앞으로 CSS를 이용해 화면을 디자인하고 JavaScript를 통해 동적인 기능을 구현하기 전에, 웹 페이지의 기본적인 구조와 사용자 입력 방식을 이해하는 과정이었다.
