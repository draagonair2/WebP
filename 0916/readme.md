HTML5 문서 구조화와 웹 폼의 이해

이번 장에서는 단순히 화면에 내용을 출력하는 수준을 넘어, HTML5 문서를 의미 있게 구조화하는 방법과 사용자로부터 정보를 입력받는 웹 폼의 구성 방식을 다루었다. 이전 장에서 여러 태그를 이용해 웹 페이지의 내용을 만드는 방법을 익혔다면, 이번 장에서는 그 내용들을 어떤 기준으로 구분하고 배치해야 하는지에 초점이 맞춰져 있었다. 특히 HTML5의 시맨틱 태그와 웹 폼은 실제 웹 페이지가 어떤 구조로 만들어지고 사용자와 어떻게 상호작용하는지를 이해하는 데 중요한 부분이었다.

가장 먼저 이해한 것은 시맨틱 태그의 필요성이다. 기존에는 <div>나 <table> 등을 이용해 영역을 나누는 경우가 많았지만, 이러한 방식만으로는 소스 코드를 보았을 때 각 영역이 어떤 의미를 가지는지 바로 파악하기 어렵다. HTML5에서는 <header>, <nav>, <section>, <article>, <aside>, <footer>와 같이 역할이 명확한 태그를 사용해 페이지를 구성할 수 있다. 예를 들어 <header>에는 페이지의 제목이나 소개를, <nav>에는 메뉴나 링크를, <section>에는 본문을, <article>에는 각각의 독립적인 내용을 배치하는 방식이다. 이렇게 작성하면 단순히 화면을 나누는 것을 넘어 문서 자체의 구조와 의미를 코드에 표현할 수 있다.

이 과정에서 특히 인상적이었던 점은 문서의 구조와 화면의 모양이 서로 다른 개념이라는 것이다. 시맨틱 태그를 사용한다고 해서 각 영역의 위치나 색상이 자동으로 정해지는 것은 아니다. HTML은 각 영역이 무엇을 의미하는지를 표현하고, 실제 크기나 위치, 배경색과 같은 시각적인 부분은 CSS가 담당한다. 실습에서는 width, height, float, clear 등을 이용해 header, nav, section, aside, footer를 배치하면서 HTML이 구조를 만들고 CSS가 그 구조를 화면에 표현한다는 관계를 직접 확인할 수 있었다.

기본적인 구조화 태그 외에도 <figure>, <details>, <summary>, <mark>, <time>, <meter>, <progress>와 같은 시맨틱 태그를 배웠다. <figure>는 이미지나 코드, 실행 결과 등을 하나의 의미 있는 단위로 묶을 수 있고, <details>와 <summary>는 사용자가 필요한 내용을 직접 펼쳐서 확인할 수 있도록 구성할 수 있다. 또한 <mark>는 중요한 부분, <time>은 시간 정보, <meter>는 일정 범위의 값, <progress>는 작업의 진행 정도를 표현한다. 실습을 통해 같은 내용을 화면에 나타내더라도 적절한 태그를 선택하면 코드가 훨씬 명확하게 읽힌다는 것을 알 수 있었다.

후반부에서는 웹 폼을 이용해 사용자 입력을 받는 방법을 학습했다. 웹 폼은 로그인, 검색, 회원가입, 예약과 같이 사용자가 직접 정보를 입력해야 하는 페이지의 기본이 된다. <form> 내부에 <input>, <textarea>, <select> 등의 요소를 배치하고, 입력 목적에 따라 text, password, checkbox, radio, number, range, color 등 다양한 형식을 사용할 수 있었다. 특히 같은 <input> 태그라도 type 값에 따라 전혀 다른 입력 방식이 만들어진다는 점이 웹 폼의 중요한 특징이라고 생각한다.

폼을 단순히 화면에 보여주는 것에서 끝내지 않고, 입력한 데이터가 실제로 어떻게 전달되는지도 살펴보았다. <form>의 action은 입력 데이터를 처리할 서버 프로그램을 지정하고, method는 데이터를 전달하는 방식을 설정하며 대표적으로 GET과 POST가 사용된다. 사용자가 값을 입력하고 submit 버튼을 누르면 브라우저가 해당 데이터를 서버로 전달하고, 서버에서 처리된 결과를 다시 브라우저에서 확인하게 된다. 이를 통해 웹 페이지가 단순한 문서가 아니라 사용자 입력과 서버의 처리가 연결되는 하나의 과정이라는 점을 이해할 수 있었다.

또한 <label>, <fieldset>, <legend>를 이용하면 폼을 더욱 체계적으로 구성할 수 있었다. <label>은 입력 요소와 그 설명을 연결하고, <fieldset>은 서로 관련된 입력 요소들을 하나의 영역으로 묶으며, <legend>는 그 영역의 제목을 나타낸다. 처음에는 단순히 입력창 몇 개를 만드는 것과 큰 차이가 없어 보였지만, 폼의 항목이 많아질수록 이러한 구조화가 코드를 이해하고 관리하는 데 중요한 역할을 한다는 것을 알 수 있었다.

이번 장을 학습하면서 HTML을 보는 관점이 조금 달라졌다. 처음에는 HTML을 화면에 글자나 이미지, 입력창을 띄우기 위한 언어 정도로 생각했지만, 시맨틱 태그와 웹 폼을 사용해보면서 HTML의 핵심은 내용에 의미를 부여하고 웹 페이지의 구조를 명확하게 만드는 것에 있다는 점을 이해하게 되었다. 결국 잘 작성된 HTML은 단순히 브라우저에서 정상적으로 출력되는 코드가 아니라, 각 요소가 왜 그 위치에 있고 어떤 역할을 하는지가 코드만 보아도 어느 정도 드러나는 문서라고 생각한다. 이번 장은 이후 CSS와 JavaScript를 활용해 더 복잡한 웹 페이지를 만들기 전에, 웹 문서의 기본적인 설계 방식을 익히는 과정이었다.
